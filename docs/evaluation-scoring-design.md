# Agent 评测打分机制

## 1. 参考案例

### OpenAI Agent Evals 与 Graders

- Agent Evals: https://platform.openai.com/docs/guides/agent-evals
- Graders: https://platform.openai.com/docs/guides/graders

优秀之处：

- 将 Agent 质量评测设计为可重复运行的评测，而不是一次人工判断。
- 同时支持规则检查、模型评分和组合评分。
- 使用 Trace grading 定位工作流级错误，而不只评价最终文本。
- 支持部分得分，适合产品发现这类没有唯一正确答案的任务。

### Anthropic: Demystifying evals for AI agents

- https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents

优秀之处：

- 强调没有单一评测方法能够捕获所有问题，需要组合多种 grader。
- Agent 评测不仅检查最终结果，还需要检查多轮执行过程和环境反馈。
- 将明确任务、测试输入、评分逻辑和结果分析视为完整评测结构。
- 建议从小规模高质量样本开始，并持续吸收真实失败案例。

### LangSmith Evaluation 与 LLM-as-a-Judge

- Evaluation: https://docs.langchain.com/langsmith/evaluation
- LLM-as-a-Judge: https://docs.langchain.com/langsmith/llm-as-judge

优秀之处：

- 将评测分为离线回归测试和线上质量监控。
- 支持规则评测、LLM Judge、人工审核与成对比较。
- 使用明确 Rubric、结构化输出和 few-shot 示例提高 Judge 稳定性。
- 将失败 Trace 回流测试集，形成持续优化闭环。

## 2. 当前项目审核

项目原有评测能力：

- 已有 `evaluationNode`、评测 Prompt、评分面板和 Trace。
- 已有总分低于 75 分触发重写的状态机逻辑。
- 已有评测结果数据库持久化与 Markdown / JSON 导出。

原有主要问题：

- 评分维度为市场、痛点、差异化、可行性、证据质量，与目标质量维度不一致。
- 多数分数为固定值，无法真实反映当前 Agent 输出。
- 虽然调用了 LLM，但模型返回结果没有参与最终评分。
- 逐步触发工作台在 MVP PRD 后无法进入评测步骤。

## 3. 新评测机制

### 评分维度

| 维度 | 权重 | 核心判断 |
|---|---:|---|
| 完整性 | 25% | 产品发现核心产物是否完整，前后结论是否衔接 |
| 可信度 | 25% | 事实、来源、引用和假设标注是否充分可信 |
| 差异化 | 20% | 是否基于竞品与替代方案形成可验证差异 |
| 可开发性 | 20% | PRD、范围、验收标准和页面结构是否足以进入开发 |
| 表达清晰度 | 10% | 输出是否结构稳定、明确且可被后续 Agent 使用 |

### 评分方式

- 默认使用确定性规则生成稳定基线分。
- 真实模型输出合法且通过 Zod Schema 时，使用规则分 70% + LLM Judge 30%。
- Mock、模型失败或 JSON 不合法时，自动回退确定性评分。
- 每个维度输出分数、权重、判断依据、扣分原因和优化建议。
- 总分低于 75 分时设置 `rewriteRequired = true`。
- 评测节点输入、输出和状态写入 Trace。

### 可信度约束

- Mock 来源不能作为真实市场事实。
- 没有真实来源时，可信度评分设置上限。
- 区分已验证事实、模型推断与待验证假设。
- 对缺少来源、事实不足和假设过多分别扣分。

## 4. 评测与多轮搜索闭环

- 行业市场分析、竞品识别和竞品分析表均输出 `evidenceLayers`。
- 每条关键结论标记为 `fact`、`inference` 或 `assumption`。
- 证据标记同时记录判断依据、来源 ID、来源链接、置信度和验证状态。
- 没有可核验来源的结论不得标记为已验证事实。
- 当可信度低于 75 分、差异化低于 70 分或可信度存在扣分项时，评测建议触发补充研究。
- 补充研究查询优先使用评测扣分原因，其次使用市场假设、竞品研究缺口和低置信度结论。
- 补充研究完成后清除旧评测结果，由用户逐步触发重新评测。
- 补充来源不会直接被标记为事实，仍需通过可靠来源或人工审核完成验证。

## 5. 后续评测建议

- 为五维评分分别建立人工标注样本与边界案例。
- 对同一输入运行多次，监控评分方差。
- 收集产品经理对评分的纠正结果，用于校准 LLM Judge。
- 将低分和重写失败的 Trace 自动加入回归评测集。
- 接入真实搜索后，单独评测来源相关性、可信度和引用覆盖率。
